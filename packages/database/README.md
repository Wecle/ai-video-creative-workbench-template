# Database

Server-side Drizzle ORM + PostgreSQL connection factory and migration configuration. No database connections or migrations run at application startup.

The authentication tables (users, sessions, accounts, verifications, jwks, workspaces, workspace_members, workspace_invitations) live in src/auth-schema.ts. That file is generated by the Better Auth CLI from services/backend/src/auth/auth.ts and must not be edited by hand: change the Better Auth configuration, then run pnpm auth:generate followed by pnpm db:generate and review the SQL. Application tables are added to src/schema.ts as later phases need them. Review the SQL and DATABASE_URL before running pnpm db:migrate against your chosen database. The initial migration was regenerated as 0000_init; do not rewrite migration history once a database has been deployed. Browser imports are blocked by the package export condition and the frontend lint boundary.

Tests: packages/database/test/migrations.test.ts applies the migrations to a freshly created database. It needs TEST_DATABASE_URL (a user allowed to create databases) and is skipped when the variable is missing outside CI.
